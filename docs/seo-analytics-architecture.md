# Phase 6 architecture and boundaries

Phase 6 retains the vanilla JavaScript/Vite, Supabase and Cloudflare Pages architecture. The user's selected noindex preview is deployed to Cloudflare project `rawatbhata-one`, branch `phase-6`, against the existing development Supabase project. Production indexing stays opt-in. Existing environment files, business/demo data and the administrator were preserved.

1. Extend request-time public HTML from merchant pages to homepage/category/explore/search pages using existing safe components and bounded RLS-protected reads. Reuse initial public data in the browser to avoid duplicate requests. Provide usable server-side pagination/search, titles/descriptions, canonical/Open Graph metadata and truthful structured data. Demo pages and filtered/search/admin/error/preview URLs remain noindex. New publications require no rebuild.
2. Add a dynamic, paginated XML sitemap containing only eligible real content and environment-aware robots.txt. Stable same-origin media URLs recheck public visibility and use public credentials; no service key for SEO reads.
3. Add a protected same-origin event endpoint. Derive event targets/cities/timestamps in SQL, preserve event-key idempotency, reject key substitution, and consume independent persistent event budgets before recording. No IP/session/referrer/search data in event records. Honor DNT/GPC and an explicit opt-out. Only qualify actually visible, loaded advertisements; never count hidden slides or server rendering as impressions/views.
4. Add database-authorized admin analytics with bounded date ranges, city-local daily trends, top listings/promotions, separate enquiry initiation/link-preparation metrics and explicit demo inclusion. Existing checkout records remain authoritative; no order/revenue claims.
5. Add pinned deployment/performance development tools, Pages configuration, static-route exclusions, runtime binding validation, production guards, local Workers-runtime smoke checks and measured Lighthouse reports. Build/test first; apply only reviewed additive development SQL; publish the requested preview after local Cloudflare authentication. Do not create a production database, remove demo data or enable production indexing automatically.
6. Run relevant SQL/security/unit/browser regressions, inspect desktop/mobile behavior, audit dependencies, check built output for configured server secrets and document concrete results, deployment URL or exact external blocker. Stop after Phase 6.

## Final implementation decisions

- Shared SEO/domain utilities and server renderers generate metadata and safe essential HTML at request time. Server and browser use the same public components and initial bootstrap data. There is no framework, build-time merchant enumeration or privileged SEO read client.
- Public routes return proper statuses and canonical paths. Sitemaps page 1,000 eligible non-demo URLs at a time. Preview sitemap output stays empty. The media route rechecks current RLS eligibility on every no-store response; private buckets stay private.
- Optional event ingestion has a separate persistent quota, narrow service-only writers and idempotent UUIDs. The admin report is an allowlist-guarded invoker, bounded to 90 city-local days. Approximate browser metrics and trusted checkout records remain separate. No visitor identifier or enquiry note is exposed by analytics.
- Production preparation explicitly requires another Supabase project, a matching canonical origin and real content. The deployer checks raw Cloudflare project metadata, refuses its production branch and scopes secrets to preview. The pinned toolchain builds and tests Functions as well as static assets.
- Hosted testing exposed a pre-existing expensive `discovery_home` query: it exceeded the anonymous statement timeout while other routes worked. Forward migration 9 selects ranked/locality-filtered listing identities before enriching display cards, materializes repeated results and scopes JIT off to that function. It preserves signature, JSON, ACLs, invoker RLS and four-card limits. No global timeout or policy was relaxed. Subsequent live six-section queries took 553–684 ms; SQL ranking/locality and hosted browser regressions passed.

Migrations 8 and 9 are applied to the authorized development project. No catalog seed was replayed. See [setup and migration effects](phase-6-setup.md), [operational guide](phase-6-guide.md), and [measured results and file inventory](phase-6-report.md). Phase 7 remains a separate task.
