# Phase 4 admin architecture

The admin remains a separate HTML/JavaScript entry point at `/admin/`, with hash routes for overview, merchants, categories, locations, promotions, homepage ranking, business hours and media. The existing public app stays sessionless. Admin password sessions use a dedicated sessionStorage key, refresh through Supabase Auth, and are verified with `getUser()` and the database-backed single-user `is_admin()` check. Auth callbacks schedule work outside the SDK callback to avoid its documented asynchronous callback deadlock. No signup, customer/merchant login or frontend email allowlist is added.

Bounded security-invoker RPCs provide admin reads and transactional business mutations. Every function explicitly requires the active allowlisted UID, and underlying RLS remains authoritative. Merchant/category/service-area/action/attribute changes are saved atomically. Categories/localities/cities are managed without changing stable existing route slugs or moving existing listings between cities. Archiving retains business/private history. Stale edits are rejected using database timestamps. Removing actively featured category membership requires deliberate unfeaturing first.

Ranking edits preserve section/category/city foreign keys and save ordered placements atomically, with accessible up/down controls and explicit visibility settings. Public rows continue to show at most four eligible entries. Ads save paused before their desktop/mobile images can be uploaded, and publication remains a separate explicit action. Schedule changes replace only the selected merchant's weekly intervals, upsert explicit special dates and remove only explicitly selected exceptions. Manual replacement/cancellation is atomic; not-yet-started overrides can be cancelled by a scoped audited deletion, while started overrides retain their real revocation timestamp.

Uploads use a same-origin authenticated endpoint with the caller's verified user JWT and RLS-protected Storage, never a service-role bypass. Native browser image decoding/re-encoding strips metadata and produces bounded WebP output; the server validates the canonical container, dimensions, type and size before upload. Only the single trusted administrator can submit files. Existing private buckets and policies remain in force. Primary replacements retain older media as gallery items; removal is explicit and protects referenced product images/active advertisement banners. Public renderers prefer the new private media over demo fallbacks.

Implementation order: migration and authorization/transaction tests; session/repository/validation utilities; admin shell and forms; authenticated media endpoint; isolated Auth/Storage HTTP fixtures and desktop/mobile workflows; documentation and approved development setup. Existing Phase 1–3 tests remain regression coverage. Auth account creation/password selection stays manual in Supabase; the allowlist can be assigned only after the user identifies that existing Auth account. Phase 5 product/Excel editing and Phase 6 general analytics/deployment are excluded.

The implementation is complete. Migration 6 provides 19 authenticated-only public admin RPCs and three private validation helpers without changing existing RLS/Storage policies. Image attachment, metadata edits and removal all check the parent revision. Removal returns its entity snapshot in the same transaction, preventing a later refetch from silently accepting another tab's revision. The browser advances revisions only for its own successful mutations and preserves unsaved ad fields. Changing city leaves the entity editor; out-of-city merchant/ad editors reject mismatched context.

Native canvas output can contain an sRGB ICC chunk, so the browser explicitly strips ICC/EXIF/XMP chunks after decoding/re-encoding before strict server validation. The server validator checks the container rather than decoding a codec. Known database rejections permit compensating a new upload; ambiguous transport failures retain potentially committed objects. Explicit image deletion unlinks metadata before requesting Storage deletion and reports any private object left for cleanup.
